# ADR-0007: Браузерні E2E-тести

Статус: прийнято
Дата: 05.11.2026 17:29

## Контекст і проблема

Потрібно перевіряти основні сценарії через інтерфейс
У сценарії видачі беруть участь користувач(біба) і працівник(Андрій) з 2 як мінімум окремими сесіями.

## Критерії вибору

Потрібна: ізоляція сесій, запуск фронтенду та API і зрозумілий код тестів

## Розглянуті варіанти

### Варіант 1: Playwright
- Переваги: 
незалежні браузерні сесії в одному тесті
звичайний async/await
запуск серверів через конфіг
- Недоліки: 
потрібно встановити браузер і підготувати сервери та тестові дані.


### Варіант 2: Cypress

- Переваги:
зручний перегляд команд і стану сторінки під час тесту.
- Недоліки:
власна черга команд
сценарій із двома незалежними користувачами потребує іншої організації перевірок

## Рішення

Обирано Playwright. Користувач і працівник працюватимуть в окремих браузерних контекстах без спільних cookies
Спочатку запускаємо тести в Chromium зі справжніми API та тестовою БД

## Наслідки
Треба підготувати очищення тестових даних та налаштувати браузер.

## Перевірка

Після реалізації мають проходити три сценарії, а тести запускаються повторно без ручного очищення даних.
