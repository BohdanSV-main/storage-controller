# ADR-0002: Використання Fastify для API

Статус: прийнято
Дата: 29.09.2026 14:20

## Контекст і проблема

Яку проблему потрібно вирішити?
Потрібно визначитись з фреймворком для сервісу щоб надалі взаємодіяти з фронтендом.
Які умови та обмеження проєкту впливають на рішення?
Застосунок розробляється на TS. Обсяг невеликий: один склад, каталог товарів, облік залишків і резервування.

## Критерії вибору

Що важливо для вибору: складність, тестованість, сумісність, підтримка або інші потреби проєкту?
Важлива підтримка TS, зручність автоматичного тестування HTTP-маршрутів та можливість розділити бізнес логіку, доступ до даних та обробку запитів. Також важлива простота через невеликий обсяг проєкту.

## Розглянуті варіанти

### Варіант 1 - NestJS із Fastify-адаптером

- Переваги:
  Пропонує готову організацію застосунку через модулі, контролери та провайдери.
  Має вбудований механізм dependency injection.
- Недоліки:
  Потрібно додатково освоїти модулі, декоратори, провайдери та правила їх реєстрації.
  Для цього проєкту додає більше початкового налаштування.

### Варіант 2 - Fastify

- Переваги:
  Має app.inject() для перевірки маршрутів без відкриття мережевого порту.
  Дозволяє поступово додавати потрібні компоненти
- Недоліки:
  Структуру сервісів потрібно визначати самостійно.
  Спосіб передачі залежностей та меж між компонентами треба підтримувати послідовно.

## Рішення

Який варіант обрано та чому він найкраще відповідає зазначеним критеріям?
Обрано Fastify.
Для проєкту достатньо цього фреймворку через простоту в роботі. Крім того важливим агрументом є наявність можливості тестувати маршрути через app.inject().

## Наслідки

- Що обране рішення спрощує?
  Створення мінімального сервера та HTTP-маршрутів, перевірку API без запуску окремого серверного процесу, поступове додавання функціональності до наявного каркаса.
- Які обмеження чи додаткову роботу воно створює?
  Потрібно самостійно підтримувати структуру, залежності сервісів потрібно передавати явно через функції або конструктори, потрібно стежити, щоб бізнес-логіка не накопичувалась в HTTP-обробниках.

## Перевірка

Як переконатися, що реалізація відповідає рішенню? Вказати відповідні файли, команди або тести.

- Fastify зазначений у dependencies файла package.json.
- Функція buildApp() у src/app.ts створює застосунок і реєструє маршрут /health.
- Тест у src/app.test.ts використовує app.inject() та перевіряє код відповіді 200 і JSON { "status": "ok" }.
- npm test запускає перевірку маршруту.
- make check запускає повний набір перевірок проєкту.
