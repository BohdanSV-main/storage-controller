# Аудит бекенду ЛР2

## Основні сценарії

Під час аудиту 20.10.2026 перевірено вхід і вихід, права USER/WORKER, доступ до власних резервів,
створення, скасування та видачу. Повторні операції не змінюють залишки двічі.

Прогін 21.10.2026:

- `npm run check` — 43 тести, форматування, lint, типи та збірка пройшли.
- `npm run test:db` — 4 сценарії PostgreSQL пройшли: ідемпотентність,
  скасування й видача, конкурентне резервування, відкат після помилки.

## Перевірка N+1

Вимірювання від 20.10.2026 через події `query` Prisma на PostgreSQL.
Пораховано SQL-запити читання репозиторіїв без підготовки даних та автентифікації.
Кожен тестовий резерв посилався на окремий товар.

| Сценарій | Кількість записів | Кількість SQL-запитів |
| --- | --- | --- |
| Каталог із залишками | 6 → 30 | 2 → 2 |
| Власні резерви з товарами | 1 → 25 | 2 → 2 |
| Активні резерви з товарами | 1 → 25 | 2 → 2 |

Перший SELECT отримує список, другий — пов’язані записи через `IN`.
Кількість запитів не зростала разом із кількістю записів; N+1 у перевірених
сценаріях не виявлено. HTTP-запит додатково читає сесію та користувача.

SQL і результати: [lab2-query-audit.json](artifacts/lab2-query-audit.json).
Поточний `test:db` не повторює вимірювання N+1.

## Топ-3 крайові випадки

1. **Число за межами PostgreSQL Int.** ID та кількість обмежені діапазоном
   1…2147483647. Некоректні значення відхиляються з HTTP 400 до запису в БД.
2. **Конкуренція за залишок.** Зміни виконуються в Serializable-транзакції;
   при P2034 — до трьох спроб. Конкурентні резерви не перевищують залишок,
   помилка зовнішнього ключа відкочує зміни.
3. **Недоступна БД.** API повертає 503 без SQL і внутрішніх деталей.
   Збій читання сесії не перетворюється на 401, невдалий вихід не вважається успішним.
   Після невизначеного результату створення повтор використовує той самий ключ і дані.

Обробка збоїв перевіряється підставленими помилками в `error-handler.test.ts`.
Перевірку реального обриву з’єднання виконано 20.10.2026.
Подробиці: [database-failures.md](database-failures.md).

## Обмеження

- Списки без пагінації; навантажувальні вимірювання ще не виконувалися.
- Немає обмеження частоти спроб входу та автоматичного очищення ключів ідемпотентності.
- `/health` перевіряє HTTP-процес, а не доступність БД.
