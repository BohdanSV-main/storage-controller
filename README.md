# Storage Controller

Сервіс для обліку та резервування товарів на одному складі.
Користувач зможе переглядати товари, резервувати потрібну кількість і скасовувати власні резерви. Працівник складу має можливість підтверджувати видачу товарів.

## Поточний стан

У першій лабораторній підготовлено сервер на Fastify і TypeScript,
маршрут перевірки працездатності, smoke-тест, інструменти перевірки
коду та Git hooks.

Каталог, резервування, робота з базою даних і мінімальний вебінтерфейс
заплановані для подальшої реалізації.

## Вимоги до середовища

Проєкт налаштовано з використанням:
- Node.js 24;
- npm 11;
- Git;
- Make для виконання `make check`.

## Встановлення та запуск

Усі команди виконуються в корені проєкту.

Встановити залежності з package-lock.json:

```sh
npm ci
```

Зібрати застосунок і запустити сервер:

```sh
npm run build
npm start
```

Сервер доступний за адресою http://127.0.0.1:3000.

Для перевірки відкрити http://127.0.0.1:3000/health.
Очікувана відповідь із кодом HTTP 200:

```json
{ "status": "ok" }
```

## Перевірки

Запустити всі перевірки:

```sh
make check
```

Ця команда викликає `npm run check`: перевірку форматування, ESLint, перевірку типів, тести та збірку.

Окремі команди:

| Команда | Призначення |
| --- | --- |
| `npm run format` | Автоматичне форматування |
| `npm run format:check` | Перевірка форматування |
| `npm run lint` | Перевірка ESLint |
| `npm run typecheck` | Перевірка типів коду застосунку |
| `npm test` | Запуск тестів |
| `npm run build` | Збірка в dist |

Markdown-файли виключені з перевірки Prettier.
Тестові файли виключені зі збірки та перевірки типів, але виконуються через Vitest.

## Git hooks

- pre-commit: перевірка форматування та ESLint.
- pre-push: перевірка типів, тести та збірка.

Husky налаштовує hooks під час встановлення залежностей у Git-репозиторії.
